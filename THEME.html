The theme, measured

Theme v3 is live on wizardry.slothlee.xyz. It is applied as branding.custom_css on app_public_config — no image, no deploy — and the source of record is [brand/theme.css](./theme.css). This document says what it sets, what changed, and what it cannot prove.

Why a v3 at all

V2 set the brand colour and the three background surfaces, which was enough to make the sign-in page look like ours. Measuring the rendered page found three leaks that no colour picker would have shown:

What v3 sets

  • Canvas — #18271c on html and body, color-scheme: dark, honey selection.
  • Ink — a five-step green-neutral scale replacing the violet-tinted one, plus chat, code and warning colours.
  • Surfaces — primary, secondary, secondary-alt, secondary-lighter, tertiary, header, textarea, and the four modifier states (hover, accent, selected, focus).
  • Honey — the brand family, including the two variables that decide whether a button reads gold on gold: --brand-primary-fill and --instance-brand-primary-fill are the label colour.
  • Type — --font-sans, --font-sans-primary, --font-display, plus element-level fallbacks so the first paint is right before React mounts.
  • Chrome — scrollbars (thin, canopy thumb, honey on hover), :focus-visible ring at 85% honey, and 140 ms transitions on interactive elements.
  • Restraint — prefers-reduced-motion kills the transitions, prefers-reduced-data drops the backdrop.

The one thing v3 changed about behaviour

Measured at 390×844: the primary button was 342×36 px, under the 44 px floor that a thumb needs. It is now 44 px tall on phones and unchanged on desktop:

On phones only, every button whose class begins with Button.module__button gets min-height:44px!important; desktop is untouched.

Two things had to be true for that to work, and both are worth recording. The selector targets a module class prefix (Button.module__button), because the hash suffix changes every build and a full class name is a rule that works until Thursday. And the declaration needs !important, because the injected stylesheet lands before the app's own sheets, so an equal-specificity rule of theirs wins on source order — the first attempt silently did nothing, and only re-measuring the button's box caught it.

What is verified, and what is not

Verified by measurement on the live page, at 390×844 and 1440×900: document and body background, the ink scale, --font-display, the input border and focus ring, scrollbar colour, and the button's height. A screenshot was reviewed for palette coherence: no violet or grey cast remains outside the deliberately muted secondary line.

Not verified: every signed-in surface. The composer, channel list, member sidebar, modals and settings screens all draw on the same token set, so they inherit the palette — but I cannot see them without an account, and a token being set is not the same as a screen looking right. This is the honest boundary of the work: the palette is proven and the screens are not.

V4 — the cute layer, and a pack of faces

Three things a colour scheme cannot do, done without an app build.

Fireflies. One fixed overlay on body::after, eight radial-gradient motes, drifting on a 52-second loop and twinkling on eleven. It is a single composited layer: transform and opacity only, pointer-events:none, will-change set. The app is lifted above it with #root{z-index:1} so nothing can be swallowed by a decoration — measured, not assumed: the overlay reports z-index 0 and pointer-events: none, a hit test at the emptiest part of the page still returns the app's own div, and prefers-reduced-motion switches the whole thing off.

A mascot that breathes. The brand panel's mark bobs three pixels over seven seconds. Small enough that you notice it only if you look, which is the point — a mascot that waves at you every time is a mascot you learn to ignore.

A lantern on the button. The primary action carries a honey glow on hover and a honey border on focus, so the one thing you are meant to press is the one thing that lights up.

The pack is twelve expressions of the same creature — brand/emoji/, 128 px, generated by brand/make-emoji.py from the same shape vocabulary as the icon, with a contact sheet at brand/emoji-sheet.png. They are art, not inventory: custom emoji and stickers still need an upload through an owner session, which is Q5. What the pack buys now is consistency — the creature has a face for tired, pleased, dubious and delighted, so later work inherits a vocabulary instead of inventing one.

Two lessons worth keeping

raw.githubusercontent.com caches by path, not by query. Bumping ?v=9 to ?v=10 served the old bytes for minutes, and two screenshots came back byte-identical — which looked like a rendering bug and was a caching one. Backdrop revisions are now new filenames: backdrop-v3.webp, backdrop-v4.webp.

app_public_config is a wrapper, not the config. The row is {"key": ..., "value": "<config as a JSON string>"}. A write that treats the wrapper as the config — or that stores the whole thing as a string — makes the API fall back to upstream defaults, and the site returns to the violet first-run palette. repair-branding.py unwraps whatever it finds, puts branding inside value, and stores one JSON object.

Still true

The art sits at a mean luminance of about 24 out of 255 in the canopy bands: present as texture, deliberate as atmosphere. What the page cannot do without an app build is put the passkey action inside the card, add placeholder and error text to the field, or give the disabled state a designed look rather than a faded one. Those are Q20.

What still needs an app build

  1. The auth composition sits top-heavy. At 390×844 the form occupies y=122 to y=294 and the lower 550 px is empty. Vertical centring is a layout change in a module the theme cannot reach safely.
  2. The disabled primary button fades to 50% opacity, which makes the CTA look muddy on an empty form. A disabled state should read as unavailable, not as a different colour.
  3. The passkey link and the primary button share the honey accent. Hierarchy currently rests on size and position alone; a secondary treatment for links would let the button own the accent.

Those three are in BACKLOG.md as Q20, because they need code and the queue is where code lives.
